# make-knowledge-cards

一个把文章转成知识卡片的 Skill。

## 1. 项目解决什么问题

读完一篇长文，过两天只记得"好像挺有道理"，具体讲了什么全忘了。做笔记又容易变成抄书——
把整篇都记下来，等于没筛选。

这个 Skill 要解决的是**筛选问题**：从一篇连贯的文章里，判断出哪些内容真正值得成为独立的知识点，
把它们拆成互不重复的小卡片，并果断丢掉其余部分。每张卡片只讲一件事，
用固定结构表达，方便复习、归档和二次分享。

它的价值不在"总结全文"，而在**敢于舍弃**。原文信息量不够时，它宁可只产出 2 张卡片，也不注水凑数。

## 2. 主要功能

- **文章转卡片**：输入一段文章，输出 5-8 张知识卡片（信息量不足时按实际数量输出，不凑数）
- **固定四段结构**：每张卡片包含「标题 / 核心知识 / 简明解释 / 例子或自测问题」
- **单点单卡**：一张卡片只承载一个知识点，可独立成立
- **自动去重**：同一知识点在不同段落重复出现时合并为一张
- **文体自适应**：识别说明文、操作教程、观点评论三类文体并采用不同抽卡重点
- **观点与事实分离**：观点型文章中每张卡都会标明"作者认为"，不把主观主张升格为事实
- **保留限定条件**：原文的"往往""可能""样本偏小"等限定会随结论一起保留
- **覆盖说明**：结尾说明哪些内容因何种原因未被成卡

**能力边界（暂不支持）**：网页抓取（URL）、PDF / 图片 / Office 文档、Anki 导出与 `.apkg`
牌组打包、图形界面。输入仅限纯文本——直接粘贴的正文，或本地 `.md` / `.txt` 文件。

> **关于图形界面**：Skill 本身不提供界面，只在对话中输出 Markdown。
> 若需要网页界面，本仓库另附一个网页应用（[`app/`](app/)）——
> 它复用同一份 `SKILL.md` 作为抽卡规则，只是把输出格式从 Markdown 适配为 JSON。
> 支持两种部署方式：**自托管**（`node server.js`）或 **Netlify Functions**
> （见 [app/DEPLOY-NETLIFY.md](app/DEPLOY-NETLIFY.md)）。
> 该应用仍不支持网页抓取、PDF 与 Anki 导出。

## 3. 安装方法

本 Skill 为纯规则型，**不包含任何脚本**，只需复制目录即可。

**安装到当前项目**（团队共享）：

```bash
cp -r skills/make-knowledge-cards <你的项目>/.workbuddy/skills/
```

**安装到用户级**（所有项目可用）：

```bash
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/
```

安装后无需额外配置。Skill 的触发由 `SKILL.md` 中的 `description` 字段驱动，
当对话内容涉及"做成知识卡片""提炼卡片""卡片化"等意图时会自动加载。

**要求**：无依赖、无环境要求。仅需宿主支持 Skill 机制（WorkBuddy / Claude Code 等兼容实现）。

## 4. 使用方法

### 方式一：直接粘贴正文

```
把下面这篇做成知识卡片：

<粘贴你的文章正文>
```

### 方式二：指向本地文件

```
读一下 tests/fixtures/01-sleep-and-memory.md，整理成知识卡片
```

支持 `.md` 和 `.txt`。文件较长时，Skill 会先通读全文再动笔，不会只读开头就产卡。

### 可选的补充要求

```
把这篇做成知识卡片，自测问题多一些
把这篇做成知识卡片，只要 5 张
把这篇做成知识卡片，存到 cards.md
```

### 结果的形式

默认直接在对话中返回 Markdown 文本。若明确要求写入文件，才会保存为文件。

## 5. 输入输出示例

### 示例 A：信息充足的说明文（输出 8 张）

**输入**（节选自 `tests/fixtures/01-sleep-and-memory.md`）：

> 睡眠并非大脑的"关机"状态。在整夜的睡眠中，大脑会经历约 4 到 6 个周期，每个周期大约 90 分钟。
> 每个周期由非快速眼动睡眠（NREM）和快速眼动睡眠（REM）交替构成，但两者的占比在夜间并不均匀：
> 前半夜的周期以深度的 NREM 慢波睡眠为主，后半夜则 REM 睡眠占比显著上升。
>
> 记忆巩固主要发生在慢波睡眠阶段。此时大脑会重放白天经历过的神经活动模式：海马体会把白天
> 新编码的信息"回放"给新皮层，新皮层据此把短时记忆整合进长期知识网络。这个过程被称为
> 系统级巩固。海马体的容量有限，更像是一个临时缓存区；新皮层的容量近乎无限，是长期存储的场所。

**输出**（8 张卡片，此处展示 2 张）：

```markdown
# 知识卡片：睡眠与记忆巩固

> 来源：01-sleep-and-memory.md　|　共 8 张卡片

---

## 卡片 3｜记忆巩固的机制

**核心知识**
记忆巩固主要发生在慢波睡眠阶段：海马体把白天新编码的信息"回放"给新皮层，新皮层据此把短时记忆整合进长期知识网络，这一过程称为系统级巩固。

**简明解释**
这是一个信息搬运与整合的过程，而非简单的休息。它发生在特定睡眠阶段，因此睡眠结构会直接影响记忆效果。

**例子**
慢波睡眠期间，海马体向新皮层回放白天经历的神经活动模式。

---

## 卡片 4｜海马体与新皮层的分工

**核心知识**
海马体的容量有限，更像是一个临时缓存区；新皮层的容量近乎无限，是长期存储的场所。

**简明解释**
两者的角色差异决定了信息必须被"搬运"：临时缓存放不下长期内容，而长期仓库不会自动获取新信息。

**自测问题**
要理解记忆为什么会从"记得住一会儿"变成"记得住很久"，需要涉及本文中的哪两个脑区？
```

### 示例 B：观点型文章（自动标注立场）

**输入**（节选自 `tests/fixtures/03-remote-work-opinion.md`）：

> 我在一家五十人左右的公司做了三年远程，坦率地说，我不认为远程办公适合所有人。
> ……我的判断是，远程办公的核心收益其实不是"省下通勤时间"。……真正的收益是注意力的连续性：
> 在办公室，你平均每十几分钟就会被一次打断；在家里，你可以拥有连续两三个小时不被打扰的时段。

**输出**（注意开头的免责说明与"作者认为"的措辞）：

```markdown
# 知识卡片：远程办公的适用条件

> 来源：03-remote-work-opinion.md　|　共 6 张卡片
> 说明：本文为观点型文章，以下卡片均记录作者主张，不代表事实性结论。

---

## 卡片 2｜远程办公的核心收益是注意力的连续性

**核心知识**
作者判断，远程办公的核心收益其实不是"省下通勤时间"，而是注意力的连续性：在办公室平均每十几分钟被打断一次，在家则可拥有连续两三个小时不被打扰的时段。

**简明解释**
作者的论证是：省下的通勤时间常被重新分配给家务和碎片化娱乐，净收益没想象中大；而对需要深度思考的工作，连续性比时间总量更值钱。

**自测问题**
按作者的观点，远程办公真正的核心收益是什么？为什么它不是省下的通勤时间？
```

### 示例 C：信息量不足时不凑数

**输入**（`tests/fixtures/04-too-short.txt` 全文）：

> 海马体的容量有限，更像是一个临时缓存区；新皮层的容量近乎无限，是长期存储的场所。
> 记忆巩固主要发生在慢波睡眠阶段，此时海马体会把白天新编码的信息回放给新皮层。

**输出**（只有 2 张，**没有凑到 5 张**）：

```markdown

> 来源：04-too-short.txt　|　共 2 张卡片

**说明**：这段输入只包含 2 个可独立成立的知识点，不足以支撑 5 张卡片。按"信息不足不凑数"的要求，输出 2 张。

---

## 卡片 1｜海马体与新皮层的分工

**核心知识**
海马体的容量有限，更像是一个临时缓存区；新皮层的容量近乎无限，是长期存储的场所。

**简明解释**
两者角色不同，这也意味着信息需要从前者"搬运"到后者，才能进入长期存储。

**自测问题**
```

**输入不支持的格式时**：若用户给出 URL 或 PDF 路径，Skill 不会猜测内容，

### Skill 与 App 的关系

抽卡规则**只有一份真源** —— `skills/make-knowledge-cards/SKILL.md`。App 启动时读取它，
注入为 system prompt。因此改规则只需改 SKILL.md，跑一次 `node sync-prompt.mjs`
再重启服务即可，不需要修改任何代码。

`app/prompt-output-contract.md` 是唯一的适配层：Skill 原本输出 Markdown 给人看，
网页应用需要 JSON 给程序用，该文件要求模型「除输出格式外，SKILL.md 的全部规则继续完全适用」。

App 的部署方式与配置项见 [app/README.md](app/README.md)。


`.gitignore` 中明确排除了 `.workbuddy/` —— 该目录存放开发过程的工作记录，
含本机绝对路径，不属于发布内容。

## 测试与校验

两个校验脚本会自动定位项目根目录（基于脚本自身位置推导），
因此在任意目录下、克隆到任意路径都能直接运行：

```bash
# 运行本项目的结构校验（检查 frontmatter、目录结构、openai.yaml 可解析性）
python tests/verify_skill.py

# 校验 LICENSE 与官方 MIT 模板正文一致
python tests/verify_license.py

# 运行官方 Skill 验证器（quick_validate.py 来自 skill-creator，不在本仓库内）
python <skill-creator>/scripts/quick_validate.py skills/make-knowledge-cards
# 输出：Skill is valid!
```

`verify_license.py` 需要联网拉取官方 MIT 模板做比对；离线环境会提示下载失败并退出。

四类测试用文章已通过验证：说明文输出 8 张、操作教程输出 8 张、观点评论输出 6 张、
信息不足的短文本输出 2 张（未凑数）。
## 设计取舍

- **零脚本**：整个 Skill 由规则和示例驱动，不引入 `scripts/`。
  卡片质量取决于语义判断，写成脚本反而会退化成机械分句。
- **规则写在 SKILL.md 里**：工作流分 7 步，配合 8 条质量红线表。
  规则是显式的，便于按测试结果迭代修补。
- **不生成文件**：默认只输出 Markdown 文本，避免在用户不知情时写盘。
