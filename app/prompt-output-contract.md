# 输出契约（本文件覆盖 SKILL.md 的「输出格式」章节）

你正在一个网页应用中被调用。调用方是程序，需要**结构化数据**，而不是 Markdown 文本。

## 唯一需要改变的地方

**忽略 SKILL.md 中「输出格式」章节的 Markdown 写法，改为只输出一个 JSON 对象。**

SKILL.md 的其余全部规则**继续完全适用，不得放松**：

- 第 1 步的过短输入判定（信息不足不凑数）
- 第 2 步的候选知识点识别与优先级
- 第 3 步的合并去重与「该被舍弃的内容」清单
- 第 4 步的排序原则
- 第 5 步的体裁适配（说明文 / 操作教程 / 观点评论）
- 第 6 步的撰写要求（标题字数、核心知识长度、例子与自测问题二选一）
- 「质量红线」全部 8 条
- 结尾的「覆盖说明」

## 输出要求

- **只输出 JSON**，不要输出任何前缀、后缀、解释性文字
- **不要用 ``` 代码块包裹**
- 所有文本使用简体中文；原文中的命令、参数、专有名词、数字**原样保留**

## JSON 结构

```json
{
  "title": "文章主题或原标题",
  "genre": "说明文",
  "insufficient": false,
  "notice": "",
  "cards": [
    {
      "title": "4-12 字的名词性短语",
      "core": "核心知识，1-2 句",
      "explain": "简明解释，2-4 句",
      "example": "例子内容",
      "quiz": ""
    }
  ],
  "coverage_note": "覆盖说明：用一句话说明哪些内容因何种原因未成卡"
}
```

## 字符串转义（最重要，务必遵守）

JSON 字符串内部**只能用中文引号**，绝不能用英文直引号 `"`。

| 场景 | 正确 | 错误（会导致 JSON 解析失败） |
| --- | --- | --- |
| 引用原文中的说法 | `这正是“睡一觉再想”的原因` | `这正是"睡一觉再想"的原因` |
| 强调某个词 | `作者用「深度工作」指称` | `作者用"深度工作"指称` |
| 嵌套引用 | `他说“所谓‘心流’”` | 任何英文双引号 |

**规则**：

- 中文内容里需要引号时，一律用 `“ ”`（弯引号）或 `「 」`
- **不要**在 JSON 字符串值里出现 `"`（英文 U+0022 直引号）
- 文本内部的换行一律用 `\n` 表示，不要直接换行
- 字符串值内不要出现制表符

**自查**：输出前扫一遍每个字符串值，确认里面没有任何英文双引号。
若原文引用了带英文引号的内容，改写为中文引号，语义不变。

## 字段规则

附：最外层 JSON 示例（注意所有引号都是 JSON 结构的一部分，字符串内部不得再出现英文双引号）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章主题。原文有标题则沿用，否则自行概括 |
| `genre` | 是 | 只能取三个值之一：`说明文` / `操作教程` / `观点评论` |
| `insufficient` | 是 | 原文只够 1-2 张卡片时为 `true`，否则为 `false` |
| `notice` | 否 | 观点型文章必须填写：「本文为观点型文章，以下卡片均记录作者主张，不代表事实性结论。」；信息不足时说明「本文只包含 N 个可独立成立的知识点」；其余情况填空字符串 |
| `cards` | 是 | 卡片数组，1-8 张。信息量充足时为 5-8 张；信息不足时按实际数量，**不得注水凑数** |
| `cards[].title` | 是 | 4-12 字名词性短语，不得是「重要概念」「第一点」这类空泛标题 |
| `cards[].core` | 是 | 核心知识，1-2 句，必须是原文可直接支撑的陈述 |
| `cards[].explain` | 是 | 简明解释，2-4 句，可类比但不得引入原文没有的新事实 |
| `cards[].example` | 条件 | 与 `quiz` **至少填一个**。优先取原文已有的例子或数据 |
| `cards[].quiz` | 条件 | 自测问题，**只写问题不写答案**；答案必须能且只能从本卡内容得出 |
| `coverage_note` | 是 | 只要做过任何取舍就必须填写；仅当原文信息量与卡片数量完全对应、无任何舍弃时，才可为空字符串 |

## 每张卡的 example / quiz 分配

- 二者填一即可，另一个填空字符串 `""`
- 整篇建议混用：约一半卡片给 `example`，一半给 `quiz`，让复习方式有变化
- 不得全部使用同一种

## 反例（不要这样输出）

```

```json                                    ← 不要用代码块包裹

```
以上就是全部卡片。                            ← 不要有收尾语
```

正确做法：响应体从 `{` 开始，到 `}` 结束，中间没有任何其他字符。
